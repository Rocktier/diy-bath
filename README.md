# 浴室柜画图工具

把客户口头描述的定制浴室柜需求，变成**可旋转的 3D 轴测图 + 正视图**，
替代手工用 SketchUp 建模（一单半小时到一小时）。
风格是客户已经习惯的 SketchUp 白模图——不是为了好看，是为了**一眼就认得**。

---

## 打开方式

**装好的话**：开始菜单里点「浴室柜画图工具」，或双击桌面快捷方式。

**没装**：双击安装包 `浴室柜画图工具_x64-setup.exe`，一路下一步。

装完就能用，**不需要装 Node、不需要装浏览器、导购员电脑上什么都不用装**
（只依赖 Windows 自带的 WebView2）。

开发时才用 `npm run dev`（需要 Node）。

## 两种看法

顶部两个页签：

| 页签 | 快捷键 | 用途 |
|---|---|---|
| **3D** | `2` | 给客户看"我家装上是什么样"。左键拖动旋转 · 滚轮缩放 · 右键平移 |
| **正视图** | `3` | 看正面布局与尺寸标注。图纸**铺满整个右栏**，导出 PNG 直接发微信 |

`R` 键重置 3D 视角。正视图没有缩放，图纸始终铺满右栏。

**两种看法来自同一份零件数据**，所以不会出现"正视图 6 个抽屉、3D 里 4 个"。
改任何参数，两个视图同时更新。

> **为什么只有正视图？** 早期版本做过正视图 / 俯视图 / 剖面图三张，
> 实际用下来导购员给客户看的是 3D，讲结构要的是正视图，
> 俯视图与剖面图从来没人要——客户看不懂剖面图。
> 2026-10-06 按用户决定彻底删除，不保留代码。
> 相关生成逻辑已从 `project.js` 移除（`plan()` / `section()` /
> `WALL_T` / `LAYOUT_LABEL` / `layoutKey()` 及四个盆剖面 path 函数）。
> 零件层（`solve.js` / `parts.js`）一行未动，正视图完全依赖它。

## 核心原则：尺寸全部自由填

**所有尺寸都是数字输入框，没有下拉、没有档位、没有任何下限上限，
也不会弹"这个尺寸不标准"的警告。**

原因：这是定制业务，不是卖成品。深度要按客户家的墙体定，高度也不该被
"盆上沿离地 850mm"这种人体工学 guideline 反推——那会打乱工厂的开料习惯。

所以：

| 你以为会有的 | 实际 |
|---|---|
| 宽度下拉选 600/800/900 | 数字框，随便填 |
| "盆宽 900 超过柜宽 1180 了" | 不提示，照画 |
| 台面高自动按盆高倒推 | 三个独立参数，加起来就是总高 |

**特例柜型下拉只是起点模板**，选了填一整套合理值，之后每个数字都能单独改。

引擎唯一替你算的是**布局**：柜体 1180 分 6 个抽屉、缝 2mm、高度比 2:1.5:1
—— 这个让人心算容易错，客户改一次就要重算。

## 参数面板

左边 6 个分组（主柜 / 台面 / 盆 / 龙头镜柜 / 标注 / 分区）**默认只展开「主柜」**，
其余折叠。**每个折叠头直接写着当前值**：

```
主柜       1180×680×500 · 落地
台面       岩板 20厚 · 外挑10
盆         台上盆 ×1 · 500×380
龙头/镜柜   龙头✓ · 镜柜✓ 780×150
标注       开 · 右侧
分区       2 个分区
```

所以「现在是多大」不用展开就能看到，只在真要改哪个时才点开。
36 个输入框全平铺的话面板要 2365px，一屏放不下（全部折叠只要 367px）。

- 展开哪几组记在本地，刷新后还在
- 顶栏有「全部展开 / 全部收起」

## 分格：填两个数字 + 选一种排列

主柜无非就是「门」和「抽屉」的组合，所以**不列预设**，直接填数字：

| 字段 | 说明 |
|---|---|
| 门（个） | 几扇门 |
| 抽屉（个） | 几个抽屉 |
| 排列 | 左右并排 / 上下分层 |

**为什么不用预设**：门数 × 抽屉数 × 排列方式，数量上去了就是几十种，
列表永远列不完。而用户真正要说的就是「两个抽屉一个门，左右排」这句话本身，
让他直接填这三个框，比从 18 个按钮里找要快。

生成规则：

- **左右**：门和抽屉并排成一排，门在左、抽屉在右（2 门 1 抽 → 门·门·抽）
- **上下**：门在下并排一层，抽屉在上上下叠（2 门 1 抽 → 下层两扇门，上层一个抽）
- 抽屉高度自动下大上小：3 个是 3:2:1，4 个以上用缓和斜率

只有抽屉时，「上下」才是常规做法（三抽、四抽都是叠的）。

### 特例柜型

盆胆格、开放格、非等宽分格这些不是「门 + 抽」能描述的，
所以单独列在下拉框里：盆胆 + 双开门 · 双盆对开柜 · 中抽大柜 · 侧柜组合。
选了就覆盖上面的三个数字。

### 自定义分格

「分格」组最下面有个折起来的**自定义分格**，可以逐条编辑分区
（加/删分区、改列宽比行高比、指定每格类型）。
引擎的 `bands` 数据模型一个字没动，只是把它露出来了。

> 这套分类参考了恒洁官网产品筛选器的「开门方式」
> （单开门 / 单抽 / 双开门 / 双抽 / 三开门 / 左单开门）、
> 箭牌的「双开门（大小门）」「单抽单门」、
> 九牧的「大抽收纳 / 大单抽 / 大抽镜灯」。
## 分区怎么填

柜体被分成若干"带"，**从下往上**。每条带再切成 **列 × 行** 的网格，
每格是一个抽屉 / 门 / 开放格 / 盆胆。

| 字段 | 怎么填 | 例子 |
|---|---|---|
| 列宽比 | 英文逗号分隔 | `1,1` 均分 · `3,1,3` 两侧宽中间窄（中抽） |
| 行高比 | 英文逗号分隔 | `2,1` 下大上小 · `2,1.5,1` 三抽递减 |
| 格子类型 | 留空 = 整条带按「类型」来 | `door,drawer,door` 逐格指定 |

格子类型可选值：`drawer` 抽屉 · `door` 门 · `open` 开放格 · `basin` 盆胆

> **盆胆**是行业术语（九牧等图册写作"主柜：右盆胆+双开门"）：
> 盆连同其下那格柜体构成的模块。双盆柜常做成「左盆胆｜中间门｜右盆胆」。
> 它在正视图上不画面板（那里是盆），但分区结构在参数面板里一眼可见。

**常见柜型叫法**（这些是导购员跟客户说的原话，填的时候照着这个来）：
双开门柜 = 门 2 · 三开门柜 = 门 3 · 双抽柜 = 抽 2 · 三抽柜 = 抽 3 ·
六抽柜 = 抽 6 · 双抽+单门 = 门 1 + 抽 2 · 上通长抽+对开门 = 抽 1 + 门 2（上下）·
盆胆+双开门 · 双盆对开柜 · 中抽大柜 · 侧柜组合（后四个走「特例柜型」下拉）

## 正视图看什么

| 看什么 | 说明 |
|---|---|
| 正面布局 | 抽屉、门、盆胆各占多大，一眼看清 |
| 尺寸标注 | 台面、盆、主柜、缝宽自动标在图上 |
| 分区 | 盆胆不画面板（那里是盆），但分区结构在参数面板里一眼可见 |

图纸用 `svg{width:100%;height:100%}` 等比铺满整个右栏（默认 `preserveAspectRatio`，
不裁切也不拉伸）。

> 早期版本接了 panzoom 做滚轮缩放 + 拖拽平移，已删除：
> panzoom 会把 `<svg>` 的 viewBox 烘焙成 `<g>` 上的 transform，
> 与 `svg{width:100%}` 互相打架，结果 1963 单位的图形只画成 291px，
> 占容器 883px 里的三分之一，剩下三分之二是空的——加了缩放功能，图反而变小了。

### 模块

依赖方向是单向的，下层不得 import 上层：

```
app.js  →  three-view.js  →  world.js  →  silhouette.js  →  parts.js
             render.js  →  project.js ─┘          ↑
                              annotate.js  →  solve.js →  spec.js
```

| 文件 | 职责 | 是纯函数吗 |
|---|---|---|
| `src/spec.js` | 默认值、预设库、`makeSpec()` | 是 |
| `src/solve.js` | 布局求解：带×行列 → 格子矩形、盆位 | 是 |
| `src/parts.js` | spec → 零件清单（`Part[]`，`x/y/z/w/h/d`） | 是 |
| `src/silhouette.js` | 零件 → 3D 场景描述（**纯数据**） | 是 |
| `src/world.js` | 工程坐标 ↔ Three.js 坐标、3D 调色板 | 是 |
| `src/three-view.js` | ScenePlan → Three.js 场景 | 否，需要 WebGL |
| `src/project.js` | 零件 → 正视图图元 | 是 |
| `src/annotate.js` | 图上文字标注文案 | 是 |
| `src/render.js` | 图元 → SVG 字符串、白模调色板 | 是 |
| `src/app.js` | 表单、预览、导出、历史、快捷键 | **否，唯一操作 DOM 的文件** |

`solve → parts → silhouette → world` 全部无 DOM 依赖，所以 Node 里直接跑测试。

**为什么要有 `silhouette.js` 这一层**：`three-view.js` 需要 WebGL，Node 里测不了。
把"画哪些零件、什么颜色、多大"抽成纯数据后，
就能在单测里断言「台上盆底面确实坐在台面顶面」「面板块数与 `Layout.cells` 一致」——
这些回归肉眼盯不住，等客户发现就是返工。

### 为什么 `render.js` 里的 `num()` 要抛错

坐标算错时 SVG **不会报错**，只会画不出来——浏览器默默忽略非法坐标。
所以 `num()` 遇到 `NaN` / `undefined` / `Infinity` 直接抛错，
把"静默画不出来"变成"测试失败"。这是本项目最重要的回归防线，别把它改成静默跳过。

### 坐标系

原点 = 墙面与地面交线、柜体外侧边缘。x 向右，**y 向上**，z 向房间内侧。

SVG 的 `viewBox` 单位就是 mm，所以描边宽度和字号也用 mm——
不同尺寸的柜子观感一致，不会大柜子线条粗、小柜子线条粗。

高度构成（自地面起算）：

```
总高 = 柜底离地 + 柜体高(cabinet.height) + 台面厚 + 盆高(台上盆才加)
```

`cabinet.height` 只指柜体本体，不含踢脚、不含台面与盆。

### Three.js 的 z 轴要取反

工程坐标 `z` 指向房间内侧（**离观察者远**），
Three.js 的 `z` 指向观察者，所以必须 `three.z = -eng.z`，
否则柜体前后颠倒。

取反是镜像，场景转向会与鼠标手势相反，所以方位角还要乘 `CAMERA_Y_SIGN = -1` 补偿。
`src/world.js` 里有测试锁死这条规则，改动前先看那里。

## 行业依据

默认值来自这些，**仅作默认值与提示，不作约束**：

| 项目 | 值 | 出处 |
|---|---|---|
| 面板缝 | 2mm | 团体标准 T/FSWA 01-2021《浴室柜》：位差度（门与门、抽屉与抽屉、抽屉与门相邻表面间距偏差）**应不大于 2.0mm** |
| 柜宽档位 | 600/700/800/900/1000/1200/1400 | 箭牌、金牌、九牧公开图册 |
| 标称 vs 实际 | 标称比柜体大 **20mm**（标称 800 → 主柜 780） | 同上 |
| 主柜深 | 470-530（530 是大品牌标配） | 同上 |
| 镜柜 | 高 650-780、深 140-180 | 同上 |
| 台面离地 | 800-900，850 最优 | GB 50763 无障碍设计要求 700-750 |
| 单盆 | 400-600，常见 500×500 | — |

**尚未实现**：锥形斜腿、竖纹玻璃门、抽屉面内嵌线框、镜柜内部分格、
带箭头的尺寸标注线、上翻门几何、转角柜 / L 型、材质纹理与投影。
