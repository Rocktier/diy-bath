# 浴室柜画图工具

把客户口头描述的定制浴室柜需求，变成**结构正确的正视图 + 俯视图 + 剖面图**，
替代手工用 SketchUp 建模（一单半小时到一小时）。
风格是客户已经习惯的 SketchUp 白模图——不是为了好看，是为了**一眼就认得**。

---

## 打开方式

双击 **`run.bat`**。

会弹出一个独立窗口（没有地址栏、没有标签页），用的是 Windows 自带的 Edge，
**不需要安装任何东西**。

也可以直接双击 `index.html`，或本地预览：

```
node serve.js          # 然后打开 http://localhost:7788/
```

## 核心原则：尺寸全部自由填

**所有尺寸都是数字输入框，没有下拉、没有档位、没有任何下限上限，
也不会弹"这个尺寸不标准"的警告。**

原因：这是定制业务，不是卖成品。深度要按客户家的墙体定，高度也不该被
"盆上沿离地 850mm"这种人体工学 guideline 反推——那会打乱工厂的开料习惯。

所以：

| 你以为会有的 | 实际 |
|---|---|
| 宽度下拉选 600/800/900 | 数字框，随便填 |
| "盆宽 900 超过柜宽 1180 了" | 不提示，照画 |
| 台面高自动按盆高倒推 | 三个独立参数，加起来就是总高 |

**预设按钮只是起点模板**，点一下填一整套合理值，之后每个数字都能单独改。

引擎唯一替你算的是**布局**：柜体 1180 分 6 个抽屉、缝 2mm、高度比 2:1.5:1
—— 这个让人心算容易错，客户改一次就要重算。

## 分区怎么填

柜体被分成若干"带"，**从下往上**。每条带再切成 **列 × 行** 的网格，
每格是一个抽屉 / 门 / 开放格 / 盆胆。

| 字段 | 怎么填 | 例子 |
|---|---|---|
| 列宽比 | 英文逗号分隔 | `1,1` 均分 · `3,1,3` 两侧宽中间窄（中抽） |
| 行高比 | 英文逗号分隔 | `2,1` 下大上小 · `2,1.5,1` 三抽递减 |
| 格子类型 | 留空 = 整条带按「类型」来 | `door,drawer,door` 逐格指定 |

格子类型可选值：`drawer` 抽屉 · `door` 门 · `open` 开放格 · `basin` 盆胆

> **盆胆**是行业术语（九牧等图册写作"主柜：右盆胆+双开门"）：
> 盆连同其下那格柜体构成的模块。双盆柜常做成「左盆胆｜中间门｜右盆胆」。
> 它在图上不画面板（那里是盆），但会在剖面图的分区示意里标出来。

**常见柜型叫法**（预设按钮就是按这些命名的，和你跟客户说话的说法一致）：
双开门柜 · 三开门柜 · 双抽柜 · 三抽柜 · 六抽柜 · 双抽+单门 ·
上通长抽+对开门 · 盆胆+双开门 · 中抽大柜 · 侧柜组合

## 三个视图

| 视图 | 横轴 | 看什么 |
|---|---|---|
| 正视图 | 宽度 | 客户 90% 看的是这张 |
| 俯视图 | 宽度 + 深度 | 盆位、双盆间距、进深关系 |
| 剖面图 1-1 | 深度 + 高度 | 柜内构造：背板、底板、层板、抽屉箱与滑轨、盆剖面。底部附**分区示意** |

剖面图底部那条「分区示意」是**柜内分格的等比缩影**，一眼看清里面怎么分。

**三个视图来自同一份零件数据**，所以不会出现"正视图 6 个抽屉、剖面图 4 个"。

## 开发

```
npm test          # 或 node test/run.js
```

**没有构建步骤。** 改完 `src/` 下的文件，刷新浏览器即可。

`package.json` 里只有 `"type": "module"` 和一个 test 脚本，**零第三方依赖**。

### 模块

依赖方向是单向的，下层不得 import 上层：

```
app.js  →  render.js  →  project.js  →  parts.js  →  solve.js  →  spec.js
                                ↑
                            annotate.js
```

| 文件 | 职责 | 是纯函数吗 |
|---|---|---|
| `src/spec.js` | 默认值、预设库、`makeSpec()` | 是 |
| `src/solve.js` | 布局求解：带×行列 → 格子矩形、盆位 | 是 |
| `src/parts.js` | spec → 零件清单（3D 盒子） | 是 |
| `src/project.js` | 零件 → 三视图图元 | 是 |
| `src/annotate.js` | 图上文字标注文案 | 是 |
| `src/render.js` | 图元 → SVG 字符串、白模调色板 | 是 |
| `src/app.js` | 表单、预览、导出、历史 | **否，唯一操作 DOM 的文件** |

`solve → parts → project → render` 全部无 DOM 依赖，所以 Node 里直接跑测试。

### 为什么 `render.js` 里的 `num()` 要抛错

坐标算错时 SVG **不会报错**，只会画不出来——浏览器默默忽略非法坐标。
所以 `num()` 遇到 `NaN` / `undefined` / `Infinity` 直接抛错，
把"静默画不出来"变成"测试失败"。这是本项目最重要的回归防线，别把它改成静默跳过。

### 坐标系

原点 = 墙面与地面交线、柜体外侧边缘。x 向右，**y 向上**，z 向房间内侧。

SVG 的 `viewBox` 单位就是 mm，所以描边宽度和字号也用 mm——
不同尺寸的柜子观感一致，不会大柜子线条粗、小柜子线条粗。

高度构成（自地面起算）：

```
总高 = 柜底离地 + 柜体高(cabinet.height) + 台面厚 + 盆高(台上盆才加)
```

`cabinet.height` 只指柜体本体，不含踢脚、不含台面与盆。

## 行业依据

默认值来自这些，**仅作默认值与提示，不作约束**：

| 项目 | 值 | 出处 |
|---|---|---|
| 面板缝 | 2mm | 团体标准 T/FSWA 01-2021《浴室柜》：位差度（门与门、抽屉与抽屉、抽屉与门相邻表面间距偏差）**应不大于 2.0mm** |
| 柜宽档位 | 600/700/800/900/1000/1200/1400 | 箭牌、金牌、九牧公开图册 |
| 标称 vs 实际 | 标称比柜体大 **20mm**（标称 800 → 主柜 780） | 同上 |
| 主柜深 | 470-530（530 是大品牌标配） | 同上 |
| 镜柜 | 高 650-780、深 140-180 | 同上 |
| 台面离地 | 800-900，850 最优 | GB 50763 无障碍设计要求 700-750 |
| 单盆 | 400-600，常见 500×500 | — |

第一版不做：转角柜 / L 型、立柱盆 / 壁挂盆、侧柜 / 吊柜 / 镜柜内部分格、
材质纹理与投影、3D 轴测图、PDF 导出、DXF 开料图、上翻门几何。
