## 1. 目标与范围

### 1.1 要解决的问题

定制浴室柜行业里，客户用自然语言描述需求（"1200 宽，双盆，上面四个抽屉下面两个门，台下盆"），
需要快速产出一张**结构正确、比例真实**的 2D 草图，用于跟客户确认方案。
目前靠 SketchUp 手工建模，一单半小时到一小时。

### 1.2 产出目标

一张**正视图 + 俯视图 + 剖面图**，风格为 SketchUp 白模（白面黑边、平色、无纹理无投影）。
客户已经习惯看这种图，不需要重新解释。

### 1.3 明确不做（第一版）

| 不做 | 原因 |
|---|---|
| 转角柜 / L 型 | 布局求解要单独一套逻辑，收益不确定 |
| 立柱盆、壁挂盆 | 无柜体，结构差异过大 |
| 侧柜、吊柜、镜内结构 | 超出主柜范围 |
| 材质纹理、渲染、投影 | 目标风格是白模，用不上 |
| 3D / 轴测图 | 容易画错，且客户确认用不上 |
| PDF 导出 | 打印用浏览器即可 |
| DXF / 工厂开料图 | 另一个项目的事 |
| 尺寸档位、下拉选项、合法性校验 | 见 §3 关键决策 |

## 2. 关键决策（ brainstorming 结论）

### 2.1 参数化引擎，而非 AI 直接画 SVG

不采用"每次让模型直接生成 SVG 代码"。理由：

1. 算不准。柜体 1180 分 6 个抽屉、缝 2mm，模型每次计算结果会有零点几的偏差，客户看得出来。
2. 改不动。客户改一个数就要整图重画，且风格必然有微妙漂移。
3. 不复用。100 单就是 100 次赌博，没有累积。

采用**参数化引擎**：几何只算一次、永远算对，改参数只重算不重画。

### 2.2 白模风格

客户已习惯 SketchUp 白模图。渲染层因此可以极薄：**纯色块 + 描边，无纹理、无渐变、无投影**。
这让绘制每个零件的代码只关心几何，颜色由调色板统一注入。

### 2.3 所有尺寸自由输入，不设档位约束

**这是本项目最重要的一条设计原则，来自业主方明确反馈：**

> 深度有时候要根据客户的墙体来定，不能按品牌洁具的成品思路来做。
> 既然是定制，那么有很多可能都需要去自定义。

因此：

- 所有尺寸字段是自由数字输入框，无下拉档位。
- 预设库**只是起点模板**，不是约束。点一下填充一套合理值，之后每个数字都能改。
- **不做任何"这个尺寸不标准"的警告或校验。**
- 行业标准数据（见 §4.4）仅用作**输入框的初始默认值**和帮助提示，不作约束。

### 2.4 唯一保留的行业逻辑是布局求解

"柜体 900 宽、分 6 个抽屉、缝 2mm、高度比 2:1:1" —— 这件事必须引擎算。
人算容易错，客户改一次就要重算。这是本工具的核心价值。

### 2.5 尺寸之间不做人体工学联动

行业 guideline 通常是"盆上沿离地 850mm"，据此反推柜体高度。
**本项目不这样做**：柜体高、台面厚、盆高是三个独立自由参数，总高是三者之和。
因为业主方按柜体高报价和开料，反推会打乱他们的工艺习惯。

### 2.6 技术路线：先网页，后 Tauri 打包

- 第一阶段：本地网页（Edge 独立窗口模式），改代码秒刷，专注迭代引擎。
- 第二阶段：引擎定型后，用 Tauri + 现有 NSIS 打包成 exe。

环境已验证可行（2026-10-03 实测）：

## 3. 架构

```
                     Spec（一份 JSON）
                          │
                          ▼
                  ┌───────────────┐
                  │  布局求解器    │  把"带×行列"翻译成具体矩形
                  │  solve()      │  纯函数，无 DOM
                  └───────┬───────┘
                          │
                          ▼
                  ┌───────────────┐
                  │  零件清单      │  Part[]：每个是带 x/y/z/w/h/d 的盒子
                  │  parts()      │  纯函数
                  └───────┬───────┘
                          │
              ┌───────────┼───────────┐
              ▼           ▼           ▼
          正视图       俯视图      剖面图
        (x,y,w,h)    (x,z,w,d)    (z,y,d,h)
              │           │           │
              └───────────┼───────────┘
                          ▼
                    风格调色板
                          │
                          ▼
                      SVG 字符串
```

**核心不变式：三个视图来自同一份 `Part[]`。**
不可能出现"正视图 6 个抽屉、剖面图 4 个"这类不一致 —— 这是很多 AI 绘图工具的通病。

### 3.1 模块划分

| 模块 | 职责 | 依赖 | 是否纯函数 |
|---|---|---|---|
| `spec.js` | 默认值、预设库 | 无 | 是 |
| `solve.js` | 带/行列 → 格子矩形 | spec | 是 |
| `parts.js` | 零件矩形 → Part[] | spec, solve | 是 |
| `project.js` | Part → 各视图图元 | spec, parts | 是 |
| `render.js` | 图元 + 调色板 → SVG | project | 是 |
| `palette.js` | 风格定义 | 无 | 是 |
| `app.js` | 表单、预览、历史、导出 | 以上全部 | 否 |

`solve / parts / project / render` 全部是无 DOM 依赖的纯函数，可在 Node 里直接跑测试。

## 4. 数据模型

### 4.1 Spec 结构

```js
{
  name: "方案名",

  cabinet: {
    width: 1180,          // 柜体净宽（不含台面外挑）
    height: 680,          // 柜体高（落地柜 = 柜体本体，不含踢脚）
    depth: 500,           // 柜体深
    mount: "floor",       // "floor" 落地 | "wall" 悬空
    toe:  { height: 90, inset: 60 },   // 仅 mount="floor" 生效：踢脚高 / 每侧内缩
    wallGap: 150,         // 仅 mount="wall"  生效：柜底离地高
    sidePanel: 18,
    backPanel: 9,
    bottomPanel: 18,
  },

  top: {
    thickness: 20,
    overhang: 10,         // 每边外挑
    backsplash: { height: 90, thickness: 18 },
    material: "岩板",      // 仅作文字标注
  },

  basin: {
    type: "vessel",       // "vessel" 台上 | "undermount" 台下 | "integral" 一体
    count: 1,             // 1 | 2
    width: 500,           // 单盆宽
    depth: 380,           // 单盆深
    height: 120,          // 台上盆高（台下盆填 0）
    position: null,       // null=按 count 自动；数字=手动指定左边界（相对柜体左边缘）
    depthBias: 0.5,       // 0=贴前沿 1=贴挡水，默认居中
    shape: "rect",        // "rect" 矩形 | "ellipse" 椭圆
  },

  faucet: { height: 150, reach: 110, enabled: true },

  mirror: { height: 780, depth: 150, led: false },   // null 表示不画镜柜

  bands: [ /* 见 §4.2 */ ],

  view: { front: true, plan: true, section: true, dims: false },
}
```

### 4.2 Band（分区带）—— 核心模型

柜体被横向分成若干"带"（从下到上），每带再切成 **列 × 行** 的网格，每格是一个抽屉 / 门 / 开放格。

```js
{
  kind: "drawer",        // 缺省格子类型
  cols: [1, 1],          // 列宽比（左→右）
  rows: [2, 1],          // 行高比（下→上）
  cells: null,           // 可选覆盖，按行优先展开，长度 = cols.length * rows.length
  handle: "bar-h",       // 见 §4.3；仅对 kind 含 drawer/door 的格子生效
  plinth: false,         // 门带是否延伸到踢脚（无独立踢脚线）
}
```

**一个模型覆盖全部需求**，无需特例分支：

| 需求 | 表达方式 |
|---|---|
| 上二抽 + 下双开 | `bands: [{kind:"door", cols:[1,1], rows:[1], handle:"bar-v"}, {kind:"drawer", cols:[1,1], rows:[2,1], handle:"bar-h"}]` |
| 3列×2行 六抽 | `{kind:"drawer", cols:[1,1,1], rows:[2,1]}` |
| **中抽/中门** | `{kind:"door", cols:[3,1,3], rows:[1], cells:["door","drawer","door"], handle:"bar-v"}` |
| **侧柜/开放格** | `{kind:"drawer", cols:[2,4], rows:[1,1,1], cells:["open","drawer","drawer","drawer","drawer","drawer"]}` |
| **无门开放格** | `{kind:"open", cols:[1,1,1], rows:[2,1,1]}` |

### 4.3 把手

`handle` 可以是字符串（整条带统一），也可以是数组（按 `cells` 的展开顺序逐格指定），
长度与 `cells` 相同。字符串形式是数组形式全部相同的简写。

| 值 | 中文 | 画法 |
|---|---|---|
| `bar-h` | 横长条 | 格子内居中，长度 = min(240, 格宽×0.6)，靠底边 34mm |
| `bar-v` | 竖长条 | 靠中缝一侧，长度 = min(260, 格高×0.5) |
| `gola` | 暗拉手 | 格子上沿一道 20mm 高凹槽 |
| `knob` | 小拉手 | 圆形 ⌀20，靠近格子角 |
| `none` | 无 | 不画 |

`gola` 在正视图与俯视图都画；`bar-h` / `bar-v` 在俯视图不画（只有立面看得到）。

### 4.4 默认值来源

输入框初始值来自行业调研（**仅作默认值，可任意修改**）：

| 字段 | 默认 | 来源 |
|---|---|---|
| `bands` 面板缝 | **2 mm** | 团体标准 T/FSWA 01-2021《浴室柜》：位差度（门与门、抽屉与抽屉、抽屉与门相邻表面间距偏差）**应不大于 2.0mm** |
| `cabinet.depth` | 500 | 行业常见 450-550 |
| `top.thickness` | 20 | 岩板 12-18，陶瓷一体盆约 10 |
| `top.backsplash.height` | 90 | 常见 60-100 |
| `basin.width` × `depth` | 500 × 380 | 单盆 400-600 |
| `basin.height` | 120 | 台上盆常见 100-150 |
| `faucet.height` | 150 | — |
| `mirror.height` / `depth` | 780 / 150 | 行业镜柜高 650-750、深 150-180 |
| `cabinet.sidePanel` | 18 | 人造板常规 |
| `cabinet.toe` | 90 / 60 | 常见离地 80-150 |

**参考信息（不作为约束，仅在帮助里显示）**：
主柜常见宽 600/700/800/900/1000/1200/1600；台面离地常见 800-900；
台面深 <700 不建议台上盆；台面深建议 ≥500。这些**不写进校验逻辑**。

## 5. 布局求解规则

### 5.1 坐标系

原点设在**墙面 / 地面交线，柜体外侧边缘**，y 轴向上，z 轴向房间内侧（由墙向内）。
中间计算用 y 向上的数学坐标，在 `project.js` 里转换成屏幕坐标时翻转。

高度构成（自地面起算）：

| 项 | 落地式 | 悬空式 |
|---|---|---|
| 柜底离地 | `toe.height` | `wallGap` |
| 柜体本体高 | `cabinet.height` | `cabinet.height` |
| 台面厚 | `top.thickness` | `top.thickness` |
| 盆高 | `basin.type === "vessel" ? basin.height : 0` | 同左 |
| **总高** | 四项之和 | 四项之和 |

`cabinet.height` **只指柜体本体**，不含踢脚，不含台面与盆。
分区带填满的就是这 `cabinet.height`。

### 5.2 竖向分配

```
1. 柜底离地 base = (mount === "floor" ? toe.height : wallGap)
2. 带间缝 = gap × (bands.length - 1)
3. 每个带占用高 = (cabinet.height - 带间缝总) × Σrowsᵢ / Σ所有rows
4. 带内按 rows 比例分配，rows[0] 在最下面
```

### 5.3 横向分配

```
1. 柜体净宽 = cabinet.width - 2 × sidePanel
2. 格间缝：列间 = gap × (cols.length - 1)
3. 每列宽 = (净宽 - 列间缝总) × colsⱼ / Σcols
4. 带内按 cols 比例从左往右分配
```

### 5.4 `cells` 展开规则

按**行优先**从下往上、同行内从左往右展开，长度必须等于 `cols.length × rows.length`。
不匹配时抛错（这是编程错误，不是用户输入错误）。

### 5.5 盆位求解

盆在台面上有两个方向的落位，互不干扰：

**X 方向（宽度）—— 相对柜体左边缘**

```
count=1, position=null  →  basinX = (cabinet.width - basin.width) / 2
count=1, position=数字  →  basinX = 该值
count=2                →  两盆整体居中：
    组宽 = basin.width × 2 + basinGap     （basinGap 默认 150）
    组左 = (cabinet.width - 组宽) / 2
    basinX[0] = 组左;  basinX[1] = 组左 + basin.width + basinGap
```

台面每边外挑 `top.overhang`，所以盆的左右必然还有富余，不构成约束。
`basin.position` 为数字时直接采用，不做居中处理，也不做边界校验（§2.3）。

**Z 方向（深度）—— 相对墙面**

```
可用 = [ backsplash.thickness,  topDepth ]
bias = basin.depthBias ?? 0.5        // 0 = 贴前沿，1 = 贴挡水
basinZ = backsplash.thickness + (topDepth - backsplash.thickness - basin.depth) × (1 - bias)
```

默认 0.5 即盆在剩余台面深度上居中。

### 5.6 三种盆的几何差异

| | 正视图 | 俯视图 | 剖面图 |
|---|---|---|---|
| **台上盆** `vessel` | 完整盆轮廓，底边坐在台面顶面 | 盆轮廓在台面之上，投影可见 | 台面 + 盆的剖面，盆为空腔 |
| **台下盆** `undermount` | **盆的外轮廓可见，嵌在台面下方**（业主方要求） | 台面开孔轮廓 + 孔内盆轮廓 | 台面 + 下方盆剖面 |
| **一体盆** `integral` | 台面与盆连成一整块，无接缝线 | 一整块，无独立盆轮廓 | 一整块料，无接缝 |

## 6. 零件与投影

### 6.1 Part 结构

```js
{ kind, x, y, z, w, h, d, meta }
```

`kind` 取值：`wall`（隐含背景）、`mirror`、`backsplash`、`top`、`carcass`、`cell`、`toe`、
`basin`、`faucet`、`shelf`、`rail`、`panelEdge`

### 6.2 投影规则

| 视图 | 横轴 | 纵轴 | 尺寸 | z 的处理 |
|---|---|---|---|---|
| 正视图 | x | y | w × h | 取最大 z（画在最前） |
| 俯视图 | x | z | w × d | y 越高越靠后（画在上方） |
| 剖面图 | z | y | d × h | 取柜体中线 x 处的截面 |

剖面图在 x = 柜体中线处剖开，画出：侧板、背板、底板、层板、抽屉箱与滑轨、
门板边、台面、盆剖面、挡水。抽屉 / 门的**分格线用虚线示意**。

### 6.3 剖面图的层板规则

层板位置**由分区自动推导**，不单独设参数：

- 每个 `kind === "door"` 的格子，若格高 ≥ 400mm，视为柜内空间，加一块层板（默认在格高中部）
- 其余情况不加

理由：这是行业惯例，且避免了让导购员理解"层板位置"这个概念。

## 7. 渲染层

### 7.1 调色板

```js
{
  wall: "#f4f4f2",  floor: "#9a9a9a",
  stroke: "#000", strokeWidth: 1,
  mirror: "#ffffff", mirrorInner: "#f0f0ee",
  top: "#dcdcda", basin: "#fbfbfa", basinInner: "#e6e6e4",
  carcass: "#d2d2d0", cellFace: "#f4f4f3",
  handle: "#c6c6c4", toe: "#c2c2c0",
  interior: "none", rail: "#a9a9a7",
  dimText: "#333333",
}
```

### 7.2 绘制规则

- 全部 `fill` + `stroke`，**无 filter、无 gradient、无 shadow、无 pattern**
- 描边宽度以 mm 为单位（viewBox 就是 mm），默认 1
- 内部分格线、虚线（俯视图的柜体轮廓、剖面图的分格）用 `stroke-dasharray`
- 尺寸标注为可选项 `view.dims`，默认关闭

### 7.3 输出

每个视图输出一个独立 `<svg>`，含 `width`/`height`（mm）、`viewBox`（mm）、
以及 `data-part-kind` 属性（便于自动化测试和调试）。

## 8. 界面

### 8.1 布局

```
┌─────────────────────────────────────────────┐
│  顶部：方案名 · 预设下拉 · 导出PNG/SVG · 历史 │
├──────────┬──────────────────────────────────┤
│          │                                  │
│  参数表单 │        预览区（三视图并排）       │
│          │        正视图  俯视图  剖面图      │
│  (可折叠) │                                  │
│          │                                  │
└──────────┴──────────────────────────────────┘
```

### 8.2 预设库（=起点模板，非约束）

点一下填入一整套合理值，**之后每个数字都能单独改**。

| 预设名 | 分区表达式（bands 顺序 = 从下到上） |
|---|---|
| 900 单盆三抽 | `[{kind:"drawer", cols:[1], rows:[2,1.5,1]}]` |
| 1200 双盆对开 | `[{kind:"door", cols:[1,1], rows:[1], handle:"bar-v"}, {kind:"drawer", cols:[1], rows:[1], handle:"bar-h"}]` |
| 1200 双盆六抽 | `[{kind:"drawer", cols:[2,2], rows:[2,1,1], handle:"bar-h"}]` |
| 800 单盆两抽（台下盆） | `[{kind:"drawer", cols:[1], rows:[2,1], handle:"bar-h"}]` |
| 600 小户型挂墙 | `[{kind:"drawer", cols:[1], rows:[2,1]}]`，`mount:"wall"` |
| 1500 中抽大柜 | `[{kind:"door", cols:[3,1,3], rows:[1], cells:["door","drawer","door"], handle:"bar-v"}, {kind:"drawer", cols:[1,1,1], rows:[2,1]}]` |

### 8.3 表单原则

- 全部尺寸为 `<input type="number">`，带 `mm` 后缀，**无下拉、无档位**
- 分组：主柜 / 台面 / 盆 / 龙头镜柜 / 分区 / 显示
- 分区编辑器：每条带一行，显示为"类型 · 列数 · 行数 · 比例"，点开可细调
- 不做任何合法性校验警告（§2.3）
- 预览实时更新（纯函数，输入即重算，无需显式"生成"按钮）

## 9. 导出与历史

### 9.1 导出

| 格式 | 实现 | 用途 |
|---|---|---|
| SVG | `Blob` + `<a download>` | 存档、给工厂、矢量编辑 |
| PNG | `SVG → Image → Canvas → toDataURL` | 发微信 |

PNG 导出参数：2 倍像素密度、透明或白底可选。
两个阶段都直接用 WebView2 的浏览器下载能力，**Tauri 阶段不引入文件系统插件**。

### 9.2 历史记录

- 每次参数变更防抖 800ms 后写入 `localStorage`
- 上限 100 条，按时间倒序
- 每条存 `{ spec, 缩略SVG dataURL(约 3KB), 时间戳 }`
- 顶部下拉可切换，点击即恢复
- 提供"清空历史"

用 `localStorage` 而非文件系统，Tauri 阶段同样可用（WebView2 支持），
因此不需要为存储写两套实现。

### 11.1 几何断言（核心）

| 用例 | 断言 | 手算 |
|---|---|---|
| 柜体宽 1180、侧板 18、2 列、缝 2 | 每格宽 = **571** | (1180 − 36 − 2) ÷ 2 = 571 |
| 柜体高 680、2 带、缝 2、rows [2,1] | 下带 = **452**，上带 = **226** | (680 − 2) × 2÷3 = 452；(680 − 2) × 1÷3 = 226 |
| 落地、柜体 680、踢脚 90 | 柜底离地 **90**，柜顶离地 **770** | — |
| 悬空、柜体 680、wallGap 150 | 柜底离地 **150**，柜顶离地 **830** | — |
| 台上盆、柜体 680、踢脚 90、台面 20、盆 120 | 总高 = **910** | 90+680+20+120 |
| 台下盆、同上但盆高 0 | 总高 = **790** | 90+680+20 |
| 单盆居中，柜体 1180、盆 500 | basinX = **340** | (1180 − 500) ÷ 2 |
| 双盆，柜体 1180、盆 500×2、盆间 150 | 组左 = **15**，第二盆左 = **665** | 组宽 1150，(1180−1150)÷2=15 |
| 盆深 380、台面深 500、挡水 18、bias 0.5 | basinZ = **78**，盆前缘离前沿 = **42** | 18 + (500−18−380) × 0.5 |
| 三视图一致性 | 剖面图分格线数量 == 正视图格子数量 | — |
| `cells` 长度不匹配 | 求解器抛错 | — |

> 本表的"手算"列是**唯一事实来源**。写测试时照抄这里的算式，不要写死常数。
> 如果测试结果和这里对不上，说明 §5 的公式或本表有一方是错的，先查文档再改代码。

### 11.2 回归

每次改动后跑全部预设 × 全部盆型 × 全部视图，产出 SVG 并做基本校验
（能解析、viewBox 非空、无 `NaN` / `undefined` 出现在属性值里）。

**`NaN` 检查是关键**：坐标算错时 SVG 不会报错，只会画不出来，必须显式断言。
