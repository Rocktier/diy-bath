### 架构一句话

```
app.js → render.js → project.js → parts.js → solve.js → spec.js
```

`solve → parts → project → render` 全是**无 DOM 依赖的纯函数**，
所以测试能在 Node 里直接跑。**正视图与 3D 共用同一份 `Part[]`**，几何必然一致。

#### 我犯过的错（勿重犯）

客户说"可以左右上下旋转"指的是 **3D 换角度**，
我上一轮加的 `panzoom` 是 **2D 放大**——解决了次要需求。

顺带发现 `panzoom` **从引入起就没工作过**：
用了 3.x 的 API，且不能作用在根 `<svg>` 上。
抛错中断 `redraw()`，导致正视图模式下只渲染出一张图。

**教训一：检查"状态对"不等于"能用"。**
`preserveDrawingBuffer` 那个 bug（3D 导出空白）就是靠读像素才发现的——
只看"canvas 存在、尺寸正确"会直接放过。

**教训二：自己写的检查脚本也会报错，要复核。**
审计脚本报"选中的页签高亮反了"，查下来是读到了 CSS `transition` 的中间帧，
稳定后完全正常。差点照着假象改 CSS。
另一头，程序化 `.focus()` 不触发 `:focus-visible`，
必须用真实 Tab 键走一遍才能测焦点环。

## 关键约束（违反即返工）

1. **所有尺寸自由输入，不设档位、不做校验、不给"不标准"警告。**
   客户原话：
   > 深度有时候要根据客户的墙体来定，不能按品牌洁具的成品思路来做。
   > 既然是定制，那么有很多可能都需要去自定义。

   表单里 `min` / `max` 属性数必须是 **0**（已写成测试）。
   **这条最容易被"好心"破坏——看到 600 的柜体宽 300 就想加个 `min`。不要加。**

2. **三个视图必须来自同一份 `Part[]`。**
   这样才不会出现"正视图 6 个抽屉、3D 里 4 个"这种不一致——
   很多 AI 绘图工具就死在这。

3. **坐标算错时 SVG 不会报错，只会画不出来。**
   所以 `render.js` 里的 `num()` 遇到非有限数**直接抛错**。
   这是项目最重要的回归防线，**别把它改成静默跳过**。

4. **白模风格：纯色块 + 描边。禁止 `filter` / `gradient` / `pattern` / `shadow`。**
   客户选白模是因为**一眼就认得**，不是嫌不好看。别自作主张加质感。

5. **`app.js` 是唯一允许操作 DOM 的文件**；下层模块不得 import 上层，
   依赖方向必须保持单向。

6. **每个任务的 `git commit` 之后必须 `git push`。**
   主开发可能在两台笔记本之间切换，未推送的提交在换机时会丢失。

## 已定死的业务决策（客户已答复，别再问）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 面板缝宽 | **2mm**，来自团体标准 T/FSWA 01-2021「位差度应不大于 2.0mm」，做成可改常量 |
| 2 | 一体盆怎么画 | **画出盆胆轮廓**，只取消台面与盆之间的接缝线。不是画成没内部结构的整块 |
| 3 | 抽屉滑轨 | **不区分**三节/两节，统一画法 |
| 4 | 图上文字标注 | **要**。内容全部由 spec 自动生成，导购员不用打一个字 |
| 5 | 预设库来源 | **按品牌通用柜型叫法**，尺寸起点取自箭牌/金牌/九牧公开图册，**全部可改** |

**第一版明确不做**：转角柜/L 型、立柱盆/壁挂盆、侧柜/吊柜/镜柜内部分格、
材质纹理与投影、3D 轴测图、PDF 导出、DXF 开料图、上翻门几何。

## 实现过程中踩过的坑（都已修，值得记住）

| 坑 | 教训 |
|---|---|
| `cols:[2]` 我以为是"两列"，实际是"一列宽 2 倍" | 想要 2×2 网格必须写 `cols:[1,1], rows:[1,1]` |
| 分区示意条原本把格子**平铺**成一条 | 不同带的格子是上下叠的，平铺后总宽 = 净宽×2，完全不代表柜子。改成等比缩影 |
| 示意条画到了地面线上方 | 屏幕 y 为正才是"地面线以下"，整条必须落在 y>0 一侧 |
| `refresh()` 每次按键重建整个表单 | 输入框失焦、光标跳位，根本没法连续输入。拆成 `rebuild()` 和 `redraw()` |
| `bbox()` 返回的 `b[2]` 我以为是右边缘 | 实际是**宽度**，返回 `[minX, minY, w, h]` |
| 双开门把手断言写成"跨越中线" | 实际是各自那扇门的靠中缝一侧，**不跨中线** |
| `PowerShell Set-Content -Encoding UTF8` 会加 BOM | 写 `.js` 会被 Node 当成有 BOM 而报错。JS 文件一律用编辑工具写 |
| `workflow 丢顶层字段 → GitHub 报 0 秒 failure 且无日志` | 加了 `scripts/lint-workflows.mjs` 接进 `npm run verify` 和 CI。GitHub 查不出原因的，提交前先拦一道 |
| 写 `.bat` 时头部被截断 | 和上一条同源。写完立刻用独立工具验首行和字节，别只信返回值 |
| npm 11 拦 esbuild 的 postinstall | `npm install-scripts approve esbuild` + `npm rebuild esbuild` |

## 行业依据（默认值和提示的来源，不是约束）

| 项目 | 值 | 出处 |
|---|---|---|
| 面板缝 | 2mm | T/FSWA 01-2021《浴室柜》位差度 ≤2.0mm |
| 柜宽档位 | 600/700/800/900/1000/1200/1400 | 箭牌、金牌、九牧公开图册 |
| 标称 vs 实际 | 标称比柜体大 **20mm**（标称 800 → 主柜 780） | 同上 |
| 主柜深 | 470-530（530 是大品牌标配） | 同上 |
| 镜柜 | 高 650-780、深 140-180 | 同上 |
| 台面离地 | 800-900，850 最优（低于 800 易弯腰） | GB 50763 无障碍要求 700-750 |
| 单盆 | 400-600，常见 500×500 | — |
| **"盆胆"** | 盆连同其下柜体构成的模块，双盆柜常做成「左盆胆｜中间门｜右盆胆」 | 九牧图册「主柜：右盆胆+双开门」 |
| 抽屉建议 | 「与其两个窄抽屉，不如一个宽抽屉，最多省 15% 收纳空间」 | 百隆官方，可做成导购话术提示 |
