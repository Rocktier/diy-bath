## 一句话

把"客户口头描述的定制浴室柜需求"变成**结构正确的正视图 + 俯视图 + 剖面图**，
替代现在手工用 SketchUp 建模（一单半小时到一小时）。
风格是客户已经习惯的 SketchUp 白模图。

### 怎么用

给导购员发安装包，双击即可。**不需要预装 Node、Edge 或任何运行时**，
只依赖 Windows 自带的 WebView2。

开发时：

```
npm run tauri:dev     # 桌面应用，改完热重载
npm run dev           # 浏览器里看，改完刷新
npm run verify        # 版本号 + workflow 语法 + 全部测试
npm run tauri:build   # 出安装包
```

### 架构一句话

```
app.js → render.js → project.js → parts.js → solve.js → spec.js
```

`solve → parts → project → render` 全是**无 DOM 依赖的纯函数**，
所以测试能在 Node 里直接跑。三视图来自同一份 `Part[]`，几何必然一致。

## 待办

### 🔴 最优先：3D 轴测图 + 模型表达力（参照图差距）

**背景**：2026-10-05 客户给出参照图，那才是真正要做的图。三视图只是过渡形态。
图已存为 `docs/reference/target-output.png`，
**逐项拆解见 `docs/reference/README.md`**（含全部尺寸标注、结构特征、差距清单），
接手时先读那份，不用重新看图分析。

**我理解错的方向**：客户说"这个图在 SketchUp 里可以左右上下旋转，
所以我让加第三方库是这个意思"——他要的是**换角度看**（3D 旋转），
而我上一轮加的 `panzoom` 是**放大看细节**（2D 缩放）。
两个完全不同的需求，我解决了次要的那个。**这是我的判断失误。**

**我还把主次搞反了**：剖面图客户其实看不太懂，
而轴测图才是客户想看的"我家装上是什么样"。

#### 差距一：我完全没有 3D 渲染层

目前只有三个正交投影面（正/俯/剖）。参照图的主体是**可轨道旋转的三维视图**，
这不是加功能，是缺一整层渲染。

**关键好消息：数据模型本来就是 3D 的。**
`Part` 结构已含 `x / y / z / w / h / d` 六个值：

```js
{ kind: 'top', x: -10, y: 770, z: 0, w: 1200, h: 20, d: 510 }
```

引入 Three.js 渲染，**数据层几乎不用改**。这是现成的优势。

方案：Three.js（MIT，SaaS 友好）+ 内置 OrbitControls（天然支持左右上下旋转）。

#### 差距二：模型表达力缺口（要改引擎，比渲染层更麻烦）

参照图里这些东西我都没有：

| 参照图里的 | 我现在 | 备注 |
|---|---|---|
| **锥形斜腿**，向外撇，总宽 1195 > 柜体 1100 | 只有「踢脚」和「悬空」两种 | 图里最显眼的特征之一 |
| **两扇竖纹玻璃门**，可见内部层板 | cells 只有 抽屉/门/开放格/盆胆 | 且无法透视 |
| **抽屉面内嵌矩形线框**（inset panel） | 纯色矩形 | 无装饰线 |
| **镜柜三门 + 柜内层板** | 镜柜是空盒子 | 无门缝、无内部分格 |
| 门上**竖向内嵌拉手槽** | 横长条/竖长条/暗拉手/圆钮 | 形状对不上 |
| 台面深色岩板、柜体米白、金属件 | 纯色白模 | 无材质 |
| 地面和投影 | 无环境概念 | — |

#### 差距三：尺寸标注线（最快能补，纯投影层）

参照图上 1170 / 780 / 140 / 500 / 1100 / 200 / 1195 都有箭头和延伸线，
我目前只有纯文字标注。`view.dims` 字段已预留，实现时只加投影层，不动引擎。

#### 执行顺序建议（待客户确认后定）

1. **先做渲染层**（Three.js + OrbitControls + 材质 + 光照，约 400-600 行新代码）。
   有了 3D 旋转立刻能看到东西，之后每补一个模型细节都能马上在 3D 里看到效果。
2. **再补模型细节**（斜腿、玻璃门、内嵌面板、镜柜分格），
   要改 spec + parts + 测试，动的是引擎核心。
3. 反过来先补模型细节的话，平面图上看不出来，等于白做。

现有正/俯/剖三视图建议**保留**，在"给工厂看结构、标尺寸"时仍然有用，
与 3D 产品图并存。

#### ⬜ 明天起床后要客户回答的三个问题

1. **斜腿**和**玻璃门**在实际产品里常出现吗？还是这张图的做法比较特殊？
   （决定模型层做到什么程度）
2. 尺寸标注箭头现在就要，还是等 3D 做完一起？
3. 材质做到什么程度——**纯色白模**（专注结构，更像 SketchUp 习惯）
   还是**岩板纹理 + 金属质感**（好看但要处理贴图授权）？

**倾向先纯色**：纹理一旦引入，岩板花纹每个品牌都不同，
做成通用贴图反而失真；纯色 3D 客户能看清结构，
也更接近客户原本习惯的 SketchUp 出图方式。

## 关键约束（违反即返工）

1. **所有尺寸自由输入，不设档位、不做校验、不给"不标准"警告。**
   客户原话：
   > 深度有时候要根据客户的墙体来定，不能按品牌洁具的成品思路来做。
   > 既然是定制，那么有很多可能都需要去自定义。

   表单里 `min` / `max` 属性数必须是 **0**（已写成测试）。
   **这条最容易被"好心"破坏——看到 600 的柜体宽 300 就想加个 `min`。不要加。**

2. **三个视图必须来自同一份 `Part[]`。**
   这样才不会出现"正视图 6 个抽屉、剖面图 4 个"这种不一致——
   很多 AI 绘图工具就死在这。

3. **坐标算错时 SVG 不会报错，只会画不出来。**
   所以 `render.js` 里的 `num()` 遇到非有限数**直接抛错**。
   这是项目最重要的回归防线，**别把它改成静默跳过**。

4. **白模风格：纯色块 + 描边。禁止 `filter` / `gradient` / `pattern` / `shadow`。**
   客户选白模是因为**一眼就认得**，不是嫌不好看。别自作主张加质感。

5. **`app.js` 是唯一允许操作 DOM 的文件**；下层模块不得 import 上层，
   依赖方向必须保持单向。

6. **每个任务的 `git commit` 之后必须 `git push`。**
   主开发可能在两台笔记本之间切换，未推送的提交在换机时会丢失。

## 已定死的业务决策（客户已答复，别再问）

| # | 问题 | 结论 |
|---|---|---|
| 1 | 面板缝宽 | **2mm**，来自团体标准 T/FSWA 01-2021「位差度应不大于 2.0mm」，做成可改常量 |
| 2 | 一体盆怎么画 | **画出盆胆轮廓**，只取消台面与盆之间的接缝线。不是画成没内部结构的整块 |
| 3 | 抽屉滑轨 | **不区分**三节/两节，统一画法 |
| 4 | 图上文字标注 | **要**。内容全部由 spec 自动生成，导购员不用打一个字 |
| 5 | 预设库来源 | **按品牌通用柜型叫法**，尺寸起点取自箭牌/金牌/九牧公开图册，**全部可改** |

**第一版明确不做**：转角柜/L 型、立柱盆/壁挂盆、侧柜/吊柜/镜柜内部分格、
材质纹理与投影、3D 轴测图、PDF 导出、DXF 开料图、上翻门几何。

## 实现过程中踩过的坑（都已修，值得记住）

| 坑 | 教训 |
|---|---|
| `cols:[2]` 我以为是"两列"，实际是"一列宽 2 倍" | 想要 2×2 网格必须写 `cols:[1,1], rows:[1,1]` |
| 分区示意条原本把格子**平铺**成一条 | 不同带的格子是上下叠的，平铺后总宽 = 净宽×2，完全不代表柜子。改成等比缩影 |
| 示意条画到了地面线上方 | 屏幕 y 为正才是"地面线以下"，整条必须落在 y>0 一侧 |
| `refresh()` 每次按键重建整个表单 | 输入框失焦、光标跳位，根本没法连续输入。拆成 `rebuild()` 和 `redraw()` |
| `bbox()` 返回的 `b[2]` 我以为是右边缘 | 实际是**宽度**，返回 `[minX, minY, w, h]` |
| 双开门把手断言写成"跨越中线" | 实际是各自那扇门的靠中缝一侧，**不跨中线** |
| `PowerShell Set-Content -Encoding UTF8` 会加 BOM | 写 `.js` 会被 Node 当成有 BOM 而报错。JS 文件一律用编辑工具写 |
| `workflow 丢顶层字段 → GitHub 报 0 秒 failure 且无日志` | 加了 `scripts/lint-workflows.mjs` 接进 `npm run verify` 和 CI。GitHub 查不出原因的，提交前先拦一道 |
| 写 `.bat` 时头部被截断 | 和上一条同源。写完立刻用独立工具验首行和字节，别只信返回值 |
| npm 11 拦 esbuild 的 postinstall | `npm install-scripts approve esbuild` + `npm rebuild esbuild` |

## 行业依据（默认值和提示的来源，不是约束）

| 项目 | 值 | 出处 |
|---|---|---|
| 面板缝 | 2mm | T/FSWA 01-2021《浴室柜》位差度 ≤2.0mm |
| 柜宽档位 | 600/700/800/900/1000/1200/1400 | 箭牌、金牌、九牧公开图册 |
| 标称 vs 实际 | 标称比柜体大 **20mm**（标称 800 → 主柜 780） | 同上 |
| 主柜深 | 470-530（530 是大品牌标配） | 同上 |
| 镜柜 | 高 650-780、深 140-180 | 同上 |
| 台面离地 | 800-900，850 最优（低于 800 易弯腰） | GB 50763 无障碍要求 700-750 |
| 单盆 | 400-600，常见 500×500 | — |
| **"盆胆"** | 盆连同其下柜体构成的模块，双盆柜常做成「左盆胆｜中间门｜右盆胆」 | 九牧图册「主柜：右盆胆+双开门」 |
| 抽屉建议 | 「与其两个窄抽屉，不如一个宽抽屉，最多省 15% 收纳空间」 | 百隆官方，可做成导购话术提示 |
